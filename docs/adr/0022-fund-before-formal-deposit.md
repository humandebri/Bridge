# Ledger funding成功後だけ正式Depositを作成する

`request_deposit`は正式Depositとは別のstable funding attemptとquota reservationを作成し、同じupdate callで固定identityのICRC-2 pullを行う。

SuccessまたはDuplicateではattemptを`EscrowedUnquoted`の正式Depositへ原子的に昇格する。結果不明では同じidentityを束縛した`FundingReconciliationHold`へ昇格する。Insufficient Allowance、Insufficient Fundsなどの確定失敗ではattemptとreservationを削除し、record、history、sequence、job、committed quotaを残さない。

retryable failureは同じidentityを120秒だけ保持する。callback消失は専用の低優先recovery scanでLedger履歴を照合し、成功なら昇格し、24時間のdedup期間後に完全な不存在を確認できた場合だけreservationを解放する。

Deposit pauseは新しいfunding reservationの作成を拒否する。reservation作成後にpauseへ遷移しても、不可逆なLedger pullの成功または結果不明は正式Depositへ昇格し、ユーザー資金を公開recordなしで滞留させない。

公開状態に`FundingPending`は存在しない。確定失敗は`FundingRejected`、一時失敗は`FundingUnavailable`として返す。本番未投入のためschema v24、wire v20へ直接置換し、旧schema migrationは提供しない。
